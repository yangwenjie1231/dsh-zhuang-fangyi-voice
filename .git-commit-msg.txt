fix(probe): 体检拿不到 PYTHONPATH + torch 路径的 aux 误报

## 两个 bug，都是实测踩出来的

### ① `timeout-no-report`：探针起不来 doctor

`runDoctor = () => envProbe(supervisor.status().launch)` —— 而 `status().launch`
**有意只暴露 `{argv, cwd}`**（对外的诊断快照，不带环境变量）。
于是 doctor 那次 spawn 缺少 `PYTHONPATH=<repo>/src`，
`python -m zfh_voice` 直接 `No module named zfh_voice` 退出 → JSON 永远不生成
→ 体检永远报 `timeout-no-report`。

对照：手动跑同一条命令 2.7 秒就出 JSON。

修：`runDoctor` 传**带 `env` 的那份 `launch`**（服务启动用的同一份）。

### ② 误导性警告："环境还没配好 —— 模型在，但文本前端辅助文件缺失"

本机真实状态：模型目录里只有 `torch_weights/` + `ref/`，没有
`G2PWModel/` 与 tokenizer —— 因为 **torch 后端的文本前端从 `gsvRoot`
（GPT-SoVITS 检出）读**，模型目录里根本不需要那套（那是 ONNX 路径的要求）。
可合成明明是成功的，却打印"去 `download_models.py` 补齐辅助包"，
用户会白折腾一轮。

两处都要改：

  · `classifyFailure(report, fallback, {backend})` —— aux 是否是硬需求
    **取决于后端**：`onnx` 必需；`torch` 不需要；`auto` 按"有 torch 权重就
    走 torch"推。torch 路径就绪（`torch_ok` + `ref_ok`）时返回新的
    `aux-not-needed-torch`（无命令，即"这不是问题"）。
  · `formatSetupGuidance(probe, docPath, {backend})` —— 原先
    `probe.ok !== true` 与"体检没拿到结果"合并成同一个分支，于是
    `classifyFailure` 里刚做好的判定**根本没机会执行**。拆开：
    只有 `ran !== true` 或**没有 report** 才算"没拿到结果"。

`ref_ok` 是两条路都致命的（还要参考音频才能合成），所以它缺失时
即使 torch 就绪也照样报 `missing-aux` —— 有反向断言盯着。
